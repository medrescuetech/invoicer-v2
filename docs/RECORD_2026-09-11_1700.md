# Session Record — 2026-09-11 17:00

## Summary

Fix `PermissionError` on startup when the application is placed in a non-writable folder such as `C:\Program Files`. Ensure the app falls back to `%LOCALAPPDATA%` for data and logs instead of crashing. Rebuild as v2.0.11.

## Root cause

The PyInstaller executable was selecting its own folder as the application base directory when a `data/` subfolder was present, even if that folder (e.g. `C:\Program Files\Invoice & Receipt Manager`) was not writable. This caused `setup_logging()` to fail while trying to create `C:\Program Files\...\logs\application.log`.

## Changes

### 1. Portable mode now requires write access

`src/invoice_manager/infrastructure/config.py`
- `_default_base_dir()` only uses the executable folder as the base when `data/` exists **and** the folder is writable (`os.access(..., os.W_OK)`). If not writable, it falls back to `%LOCALAPPDATA%\InvoiceReceiptManager`.

### 2. Logging setup is resilient to permission errors

`src/invoice_manager/infrastructure/logging_setup.py`
- Added `_can_write_dir()` to test actual write access.
- Added `_fallback_log_dir()` returning `%LOCALAPPDATA%\InvoiceReceiptManager\logs`.
- `setup_logging()` now falls back through the preferred log directory → `%LOCALAPPDATA%` → current working directory's `logs/` subfolder.
- `_add_file_handler()` now silently skips file logging if the path is not writable, preventing startup crashes.
